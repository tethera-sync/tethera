Tethera bugs and improvements

TL;DR

Six actionable defects or boundary gaps and two improvements. Prioritize reliable watcher coverage and honest health reporting, then legal-path support and consistent IPC sender checks. No implementation changes were made.

1. Goal

Find actionable bugs and improvements without changing implementation. Audit snapshot: commit 3e293fb, initially clean worktree, 2026-09-08.

2. Codebase understanding

Bun workspace; Electron main orchestrates live scans, watchers, authenticated peers and archive application. Sandboxed React uses a narrow preload bridge. Rust sync-storage owns SQLite mapping revisions, tombstones, baselines, operations and replacement journals; sync-protocol and authenticated stdio RPC cross the language boundary. The actual archive implementation is ahead of parts of the architecture document.

This is a targeted cross-area audit of watcher reliability, path handling, IPC registration, archive history/restore and documentation. Rust archive query/schema and desktop call sites were inspected; this is not an exhaustive review of every crate, cryptographic construction, or release pipeline.

3. Recommendation

First fix watcher correctness and truthful health (F1–F3, F5) as one cohesive task. Second fix path containment false positives (F4) with focused safety regressions. Close IPC guard parity (F6) before expanding privileged UI capabilities. No critical data-loss defect was established in this review.

Findings by priority

High: F1 — Watch degradation never reaches the product

Evidence: apps/desktop/src/main/index.ts:1802; apps/desktop/src/main/continuous-sync.ts:255

Confirmed by call-site inspection. The only production FolderChangeMonitor constructor passes three arguments; the fourth onWatchHealth callback is omitted. After startup, depth/descriptor-limit failures can leave partial native coverage without a user-visible warning, even though unit tests exercise a supplied callback.

Implementation: Wire health reporting into folder state/activity with a durable-in-memory health projection that normal sync status updates cannot erase. Say periodic checks remain available only when the fallback timer is actually running. Do not mark files converged merely because watchers recover. Test production wiring, repeated degradation and recovery.

Change risk: Medium: status integration must preserve conflict and transfer priorities.

Medium: F2 — Debounce loses directory-refresh intent

Evidence: apps/desktop/src/main/continuous-sync.ts:241

Confirmed control-flow defect. A rename schedules refreshDirectories=true, but a subsequent change cancels that timer and replaces it with false. A new subdirectory can remain unwatched until the five-minute fallback. A continuous event stream can also indefinitely postpone this trailing-edge callback.

Implementation: Latch pending directory-refresh intent across the debounce window; consume it when work starts and clear it on close. Preserve events arriving during an active refresh for a subsequent pass. Add deterministic rename-then-change and close tests. Consider a maximum debounce delay as a separate bounded-latency improvement.

Change risk: Low to medium: avoid duplicate concurrent scans and callbacks after close.

Medium: F3 — Watcher health can falsely report recovery

Evidence: apps/desktop/src/main/continuous-sync.ts:247; apps/desktop/src/main/continuous-sync.ts:259; apps/desktop/src/main/continuous-sync.ts:308

Confirmed control flow. Individual watch() failures are caught inside replaceWatchers, so the refresh promise resolves and reportRecovered immediately clears the degradation. Async watcher errors silently remove coverage. The deduplication key includes each directory, so descriptor exhaustion can emit one report per rejected directory despite the comment promising deduplication.

Implementation: Make a refresh return an aggregate coverage result; report recovered only when every intended directory is watched. Include async watcher errors in health, retry coverage through the existing periodic refresh, and aggregate descriptor failures. Test partial rejection, repeated rejection, asynchronous error and true recovery before enabling F1 UI reporting.

Change risk: Medium: health must reflect coverage, not simply a fulfilled promise.

Medium: F4 — Legal double-dot-prefixed names are rejected

Evidence: apps/desktop/src/main/path-safety.ts:31; apps/desktop/src/main/folder-manifest.ts:459; apps/desktop/src/main/file-transfer.ts:93; apps/desktop/src/main/initial-sync.ts:266; apps/desktop/src/main/continuous-sync.ts:344

Reproduced with the real exported helper: resolveWithinRoot("/tmp/tethera-audit-root", "..notes/file.txt") throws an escape error, while notes/file.txt succeeds. startsWith("..") confuses a valid component with the parent component. Equivalent checks can skip hashing/watching or reject transfer.

Implementation: Use component-aware containment: relative equals "..", starts with ".." plus the host separator, or is absolute. Inspect all owning checks and reuse a narrow existing boundary where appropriate. Keep explicit dot/dot-dot input rejection and all symlink/canonical revalidation. Add valid ..notes cases and malicious sibling/traversal cases across Linux and Windows representations.

Change risk: Medium: path safety is sensitive; never fix this by removing containment checks.

Medium: F5 — A synthetic filename causes incorrect watch pruning

Evidence: apps/desktop/src/main/continuous-sync.ts:350; apps/desktop/src/main/folder-manifest.ts:323

Reproduced predicate mismatch: isManifestPathIgnored("docs/placeholder", ["**/placeholder"]) is true, while docs/keep.txt is false. The watcher uses the former to prune docs entirely, even though eligible files exist there. Periodic scanning may still find changes, but timely notification is lost.

Implementation: Expose or reuse the manifest directory-aware matching semantics instead of guessing with a child filename. Compile rules once per collection where practical. Test a filename-only placeholder ignore alongside retained subtree exclusions such as **/node_modules/**.

Change risk: Medium: preserve directory-only and explicit subtree ignore semantics.

Medium: F6 — Sender authorization is inconsistent across IPC handlers

Evidence: apps/desktop/src/main/index.ts:3360; apps/desktop/src/main/index.ts:3445; apps/desktop/src/main/index.ts:3502; apps/desktop/src/main/index.ts:3569; apps/desktop/src/main/index.ts:3588

Confirmed missing checks, not a demonstrated remote exploit. Recovery, preview and update handlers call requireTrustedMainRenderer; directory browsing/creation, mapping removal, pause and pairing revoke ignore their sender. A caller able to invoke these channels from another frame/window is not rejected by the same main-frame boundary. Existing sandbox/navigation controls reduce exposure.

Implementation: Apply the existing trusted-main-renderer guard consistently before reads or effects, with a small registration pattern only if it improves clarity. Audit argument validators separately; TypeScript annotations are not runtime validation. Test wrong webContents, subframe, destroyed window and allowed main frame with zero side effects for denied calls.

Change risk: Medium: test legitimate renderer startup; no claim of an existing remote exploit.

Medium: I1 — Older retained versions are unreachable in the browser

Evidence: apps/desktop/src/main/archive-history.ts:5; apps/desktop/src/main/archive-history.ts:122; apps/desktop/src/renderer/components/archive-history-view.tsx:247; crates/sync-storage/src/version_archive.rs:533

Confirmed product limitation, explicitly acknowledged by the UI. Main returns at most 200 recent versions and the renderer only says older history exists. There is no path to select an older version through this browser.

Implementation: Add bounded keyset pagination using (created_at, id), with matching Rust protocol, RPC validation, preload and renderer contracts. Test stable ordering when timestamps tie and when new versions arrive. Keep retention/pruning as a separate safety project.

Change risk: Medium: cross-stack contract change; do not replace paging with an unbounded fetch.

Low: I2 — Architecture and README describe obsolete boundaries

Evidence: README.md:19; docs/02-ARCHITECTURE.md:41; docs/15-IMPLEMENTATION-STATUS.md

Confirmed documentation drift. README says general archive browsing is not implemented, while the active-folder browser exists. Architecture labels per-file journals and archives planned although Rust storage owns them. It also prescribes renderer libraries absent from the desktop dependency list.

Implementation: Refresh existing documentation from live code, clearly label future topology, and retain limitations for removed-folder history, paging, retention and physical cross-platform proof.

Change risk: Low: documentation-only; no architecture rewrite required.

4. Scope

In scope: the listed defects, regression coverage, bounded history browsing and accurate documentation, in separate focused changes. Out of scope: deletion/rename propagation, archive pruning, moving transport into Rust, dependency upgrades and a broad main-process rewrite.

6. Implementation plan

  1. Reproduce watcher scheduling and coverage-report failures using controlled event ordering and minimal test seams. Preserve current native temp-directory tests.
  2. Implement F2 refresh-intent retention and F5 directory-aware ignore matching.
  3. Implement F3 aggregate health before wiring F1 production reporting. Make warning recovery depend on actual restored coverage.
  4. In a separate change implement F4, checking canonical containment consumers and malicious-path regressions.
  5. Implement F6 using the existing sender guard before effects and test denied senders.
  6. Schedule I1 paging independently; update I2 documentation to describe actual behavior.

7. Code quality rules

No any, weakening casts, dependencies or unrelated refactors. Reuse domain types and ignore matching. Keep renderer, preload, main and Rust ownership intact. Never weaken staged-write, digest verification, no-replace, transaction or recovery guarantees. Tests use temporary synthetic roots only.

9. Acceptance criteria

  • Rename followed by change cannot cancel a required directory refresh; close suppresses subsequent work.
  • Filename-only ignores never suppress watching eligible descendants.
  • Partial watch failures remain degraded, repeated failures are bounded, and true coverage recovery clears the warning.
  • Production displays degraded coverage without masking conflicts or inventing convergence.
  • Legal double-dot-prefixed names work while traversal and symlink escapes remain rejected.
  • Privileged IPC rejects unauthorized frames before effects.
  • Optional paging reaches older retained versions without an unbounded response.

10. Risks and notes

Watcher fallback generally delays changes rather than losing user files; do not describe missing native coverage as proven data loss. Path and IPC changes need security regressions. Archive retention is intentionally absent and should not be added casually: unfinished and recovery-required journal references must remain protected. Keep current architecture; do not begin with a large index.ts split. The planning artifacts are the only files written by this audit.
