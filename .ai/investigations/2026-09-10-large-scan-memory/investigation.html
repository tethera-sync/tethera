Large-scan memory: investigation and fix plan

TL;DR

The code confirms memory grows with complete manifests and several additional representations, and abandoned requests keep scanning. A persistent post-scan memory leak has not been demonstrated. First measure Electron, stop abandoned work, reuse hashing buffers, and remove unnecessary comparison allocations. Genuine million-file support then needs bounded scan pages and Rust-owned staged observations; simply increasing limits cannot solve it.

1. Goal

Keep Tethera responsive during huge file and directory scans, bound simultaneous work and transport allocations, release resources on completion/cancellation, and preserve complete-scan safety before reconciliation. The user reported concern about memory leaks when scanning an absurd number of files/folders; no process profile, file count, failing log, or repeatable post-scan retention trace was supplied.

2. Current ownership and evidence

Bun/Electron main owns live walking, SHA-256 hashing, peer transport and orchestration. React receives summaries. Rust sync-storage owns durable reconciliation, operations and recovery state. The preliminary Rust scanner is not the live desktop path and uses a different digest contract (docs/15-IMPLEMENTATION-STATUS.md:80–102). Preserve these boundaries for the initial fixes.

3. Recommendation

Use two implementation milestones. Milestone A is a focused stabilization change: cancellation, bounded admission/queues, buffer reuse, comparison allocation reduction and explicit capacity errors. Milestone B is a separately reviewed cross-stack change introducing complete staged scan generations and paged consumption. Do not describe A as unlimited-folder support. Keep the existing user preference intact; explain unsupported legacy capacity instead of silently lowering it or reconciling a prefix.

4. Scope and invariants

In scope: scan lifetimes, memory ownership, resource budgets, comparison summaries, peer framing and eventual staged observations. Out of scope: deletion/rename propagation, automatic conflict winners, cryptography changes, renderer access to SQLite, wholesale Rust scanner migration and unrelated path/watch-health defects already recorded in the previous audit.

Keep exact mapping authorization, ignore pruning, reserved staging exclusions, symlink containment, stable-read checks, full SHA-256 transfer hashes, staged writes, archive-before-replacement and journal recovery. Incomplete, cancelled, failed, unreadable or truncated observations must never be treated as complete input to sync. Partial previews may remain explicitly marked truncated.

6. Implementation sequence

  1. Establish a repeatable baseline. Add an opt-in synthetic stress harness using app-managed temporary roots. Measure Electron main, renderer and Rust RSS independently; main heap/external/arrayBuffers, active scan count, queue bytes and file/directory handles. Record runtime versions, peak, settled values and latency for 10k/100k/1m entries, deep trees, empty-directory trees, small files and long Unicode paths. Warm up then repeat identical scans at least ten times, dropping result references. Use heap snapshots/retainer paths if settled heap rises; RSS alone is not leak proof. Start small and stop before exhausting the host. Never run against real sync folders.
  2. Cancel read-only work at its owner. Add AbortSignal to scan options and propagate it from preview supersession/window teardown, peer socket close/deadline, pause/removal and shutdown. Abort sibling scans when a paired operation fails. Check before/after awaits and between hash chunks; abort must escape the broad per-file catch, not increment unreadable and continue. Close directory iterators and handles in cleanup and release operation slots in finally. Cancel watcher directory collection on close. Do not abruptly cancel an archive/replacement commit; scope this work to pre-commit scanning.
  3. Bound admission and inbound work. Reuse existing cycle/session limits, adding one small scan coordinator only if existing ownership cannot cover preview, initial merge and inbound scans. Use a documented process-wide active-scan budget with a bounded pending queue; coalesce only requests with identical root, mapping revision, rules, limits and hash mode. Release local scan permits before waiting for peer work to prevent reciprocal deadlock. Cancel queued requests too. Bound peer queued message count and bytes, validate expected frame state, close on overflow, and clear queue/buffer on terminal errors. Test fragmented and multiple-line delivery without weakening authentication.
  4. Remove avoidable allocations. Allocate one lazy 512 KiB hash buffer per scan (or active hashing worker), reuse it sequentially and avoid allocating for empty files. Populate comparison maps directly; compare in two passes without a global union/sort when output equivalence is preserved. Keep the existing top-14 sample ordering and Windows warning semantics. Cap retained display-only warnings at existing output limits, while retaining sufficient case-fold lookup state to detect collisions correctly. Validate untrusted peer manifests before comparison, including duplicates, lengths, numeric fields and digest rules, without treating transfer validation and preview truncation identically. These checks complement wire byte limits; post-parse validation cannot prevent JSON allocation.
  5. Fail early at legacy capacity boundaries. Check reconciliation capacity before invoking Rust and enforce a byte budget while collecting a legacy response, accounting for JSON escaping, UTF-8, encryption/base64 and envelope overhead. A byte-limited preview can report truncation; sync must fail closed with a recoverable limit error. Never send a partially complete observation as an empty or complete manifest. Do not increase MAX_LINE_BYTES or Rust MAX_FILES as the fix.
  6. Implement staged generations for true large-folder support. Keep traversal in main initially; send bounded, validated batches over authenticated RPC into Rust-owned SQLite staging. Generation identity binds participant, mapping/revision, canonical owning root, scan rules/hash mode and sequence. Define begin/append/seal/abort and cursor read contracts in sync-protocol and matching TS parsers. Duplicate identical batches are idempotent; changed duplicates, gaps, stale mapping revisions and cross-peer cursors fail. Seal only after EOF with verified counts/completeness; interrupted generations never advance baselines or replace active state. Use short transactions for ingestion, no open database transaction across network/filesystem work, bounded disk quota/expiry, startup cleanup and migration/newer-schema refusal tests.
  7. Consume pages end to end. Peer manifest pages must be bounded by encoded bytes as well as entry count, authenticated to the same immutable sealed generation, with cancellation and backpressure. Negotiate capability; legacy peers retain explicit legacy limits. Reconciliation must use indexed/keyset reads or ordered merges over SQLite, not reload complete generations into HashMaps/BTreeSets. Atomically publish a completed reconciliation plan without exposing a partial plan; retain recovery-journal guards and exact operation preconditions. Page initial-merge planning, replay operations, conflicts and UI summaries too. Pin both sealed generation IDs during a comparison and retain existing pre-transfer revalidation; filesystem scans are observations, not atomic filesystem snapshots. Budget/stream directory frontier state as well as files, or fail explicitly at a tested depth/resource bound.

Suggested delegation: cheap read/test worker for the harness; cheap implementation worker for isolated buffer/comparison changes; stronger worker for cancellation once the lead defines ownership. Lead owns the generation/protocol/migration design. Run storage, protocol and caller changes sequentially where contracts overlap, then obtain an independent review. Workers must not recursively delegate.

7. Code quality

No any, unchecked casts, arbitrary sleeps, forced GC in production, giant new generic service, extra dependencies or unrelated refactors. Reuse current contracts and validators. New modules must protect a real ownership/resource invariant. Update existing implementation-status, protocol, data-model and testing docs when boundaries move.

8. Validation

Executed during this investigation: bun test apps/desktop/tests/folder-manifest.test.ts apps/desktop/tests/continuous-sync.test.ts: 26 passed, 0 failed, 92 assertions. Synthetic in-process Bun comparison: two 300,000-entry manifests yielded 300,000 identical entries, about 357 ms comparison and 308,146,176 bytes RSS (~294 MiB). This used synthetic objects, shared path strings and sequential size cases, not disk scanning, a leak profile or isolated peak sampling; do not use its timings/heap counters as an Electron performance guarantee.

For implementation, test cancellation mid-directory/mid-hash/remote-disconnect, repeated abort/retry, queue overload, prompt resource release, ignored huge subtrees, deterministic samples, collision limits, malformed peer data, encrypted byte boundaries, duplicate/out-of-order batches, restart/disk-full, stale revisions, partial-generation invisibility, and reciprocal scan admission without deadlock. Compare counts/digests/plans to the old implementation on bounded fixtures.

9. Acceptance criteria

  • Repeated completed/cancelled scans leave no live scan jobs, queued waiters or orphan handles; watcher counts return to expected configured coverage. Post-GC test profiles show no accumulating scan retainers.
  • At most the documented number of scan jobs and queued bytes are active. Closing a request stops future scan work at the next cooperative checkpoint; cancellation is never reported as successful completion.
  • Milestone A preserves comparison and sync results and reports capacity failures without changing files or baselines. Measured allocation/peak improvements are reported with identical fixtures.
  • Milestone B processes a million synthetic entries without accumulating full manifests/observations on either side of a boundary. At fixed concurrency/page limits, scan working memory is bounded by page/frontier budgets, not total file count. Establish numeric machine-specific budgets from the baseline harness and record them before acceptance.
  • Every generation and durable plan is complete or invisible; retries/restarts preserve recovery evidence. Full validation and Electron evidence are recorded, with untested platforms stated explicitly.

10. Risks, review and limits

Paging without immutable generations can skip or duplicate entries. Reconciliation of incomplete scans can manufacture absence and corrupt planning. A global scan slot held across peer waits can deadlock two devices. Buffer reuse must never cross simultaneous hash operations. Do not trim warning arrays in ways that silently change preview equality or collision behavior.

Two read-only investigations ran on explicitly selected gpt-5.6-luna after Claude Haiku returned a weekly-limit error before inference. The lead checked source and accepted the allocation and cancellation findings. Corrections: a fixed-size buffer is allocated per file, not reused; transfer paths already have validation, so the missing-validation claim is narrower for preview; truncated previews need not be rejected. Existing watcher cleanup and cycle limits are real and should be retained. Actual billed savings were not available. No implementation, Electron profile, full suite or Linux-to-Windows run was performed.
